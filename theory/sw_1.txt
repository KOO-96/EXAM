# 소프트웨어 구축

### 소프트웨어 생명 주기
1) 프로젝트 계획 -> 2) 요구 사항 분석 -> 3) 소프트웨어 설계 -> 4) 소프트웨어 구현 -> 5) 테스트 -> 6) 유지 보수

### 폭포수
-> 선형 순차적 개발 / 고전적,전통적 개발 모형 / Step-By-Step
### 프로토 타입
-> 고객의 need 파악을 위한 견본 / 시제품을 통해 최종 결과 예측 / 요구사항 변경에 용이함
### 나선형
-> 폭포수 + 프로토 타입 + 위험 분석 기능 추가
-> 계획 수립 > 위험 분석 > 개발 및 검증 > 고객 평가
### 애자일 
-> 일정 짧은 주기를 반복하며 개발 진행 / 유연힌 대응이 가능하다.

### 하향식 설계
절차 지향(순차적) / 최상위 컴토넌트 설계 후 하위 기능을 부여

### 상향식 설계
객체 지향 / 최히위 모듈 먼저 설계 후 결합하고 검사

## 익스트림 프로그래밍(XP, eXtreme Programming)
- 고객의 요구사항을 유연하게 대응하기 위해 고객 참여와 신속한 개발 과정을 반복한다
- 5가지 핵심 가치 : 용기 / 단순성 / 의사소통 / 피드백 / 존중
- 기본 원리 : 전체 팀 / 소규모 릴리즈 / 테스트 주도 개발 / 지속적 통합 / ... 개발 문서보다는 소스코드에 중점을 둔다(문서화 X)

1) 프로젝트 계획
하향식 비용 산정 기법
    - 전문가 감정 기법
        - 조직 내 두 명 이상의 전문가에게 비용 산정을 의뢰
    - 델파이 기법
        - 한 명의 조정자와 여러 전문가의 의견을 종합하여 선정

상향식 비용 산정 기법
    - 프로젝트 세부 작업 단위 별 비용 정산 후 전체 비용을 산정
    종류
        - LOC(Source Line Of Code)
            - 코드 라인 총 수 / 생산성 / 개발 참여 인원등으로 계산한다.
            - (a + 4c + b) / 6
        - 개발 단계별 인월 수(Effort Per Task)
            - LOC 기법 보완 / 생명 주기 각 단계별 선정
수학적 비용 산정
    - COCOMO(Constructive Cost Model)
        - 보헴 제안 / 원시코드 라인 수 기반
        유형
            - 조직형
                -5만 라인 이하
            - 반분리형
                - 30만 라인 이하 트랜잭션 처리
            - 내장형
                - 30만 라인 이상 최대형 규모
    - PUTNAM
        - SW 생명주기 전 과정에 사용될 노력의 분포를 이용한 비용 산정
        - SLIM
            - Putnam 기초로 개발된 자동화 추정 도구
    - Function Point(FP)
        - 중대 요인에 가중치 부여 후 합산하여 기능점수 산출
        - ESTIMACS
            - FP 모형을 기반으로 하여 개발된 자동화 추정 도구

### 개발 일정 산정
- WBS(Work Breakdown Structure)
    - 전체 프로젝트를 분할 / 업무 세분화

### 네트워크 차트
- PERT(Program Evaluation and Review Technique) 
    - 불확실한 상황
- CPM(Critical Path Method) 
    - 확실한 상황

2) 요구 사항 분석
요구 사항 : 어떠한 문제를 해결하기 위해 필요한 조건 및 제약사항을 요구사항
    - 유형
        - 기능적
            - 실제 시스템 수행에 필요한 기능 관련 요구사항
        - 비기능적
            - 성능 / 보안 / 품질 / 안정성 등 보조적인 요구 사항

요구사항 개발 프로세스 (순서 중요)
    - 1) 도출 / 추출
        - 이해 관계자들이 모여 요구사항 정의
    - 2) 분석
        - 사용자 요구사항에 타당성 조사
    - 3) 명세
        - 요구사항 체계적 분석 후 문서화
    - 4) 확인 / 검증
        - 명세서가 정확하게 작성된건지 검토

요구사항 분석 도구
    - 요구사항 분석 CASE
        - SADT / SREM / PSL, PSA / TAGS
    - HIPO
        - 하향식 설계 방식 / 가시적, 총체적, 세부적 다이어그램으로 구성

구조적 분석 모델
    - 데이터 / 자료 흐름도(DFD, Data Flow Diagram)
        - 프로세스 : 원
        - 자료 흐름 : 화살표
        - 자료 저장소 : 평행선
        - 단말 : 사각형
    - 자료 사전
        - = : 정의
        - [ ] : 택일 / 선택
        - ( ) : 생략
        - + : 구성
        - ** : 설명 / 주석
        - { } :  반복

객체 지향 분석 모델
- Booch : 미시적 / 거시적 개발 프로세스 모두 사용
- Jacobson : 유즈케이스 사용
- Coad-Yourdon : E-R 다이어그램 / 객체 행위 모델링
- Wirfs-Brock : 분석과 설계 구분 없음
- ⭐️Rumbaugh(럼바우) : 가장 일반적으로 사용, 객체 / 동적 / 기능 모델로 구분
        - 객체 모델링
            - 객체 다이어그램 / 객체들 간의 관계 규정 및 정의
        - 동적 모델링
            - 상태 다이어그램 / 시스템 동적인 행위 기술
        - 기능 모델링
            - 자료 흐름도

요구 사항 명세
- 정형 명세
    - 수학적 원리
- 비정형 명세서가
    - 자연어, 그럼 중심

3) 소프트웨어 설계
설계 원리
    - 분할과 정복
        - 여러 개의 작은 서브시스템으로 나눠서 각각 완성
    - 모듈화
        - 재사용성 향상
        - 모듈 크기 🔺 -> 모듈 개수 🔻 -> 통합 비용 🔻 (BUT, 모듈당 개발 비용 🔺)
        - 모듈 크기 🔻 -> 모듈 개수 🔺 -> 통합 비용 🔺
    - 추상화
        - 문제의 포괄적인 개념을 설계 후 차례로 세분화하여 구체화 진행
            - 과정 추상화
                - 자세한 수행 과정 정의 X / 전반적인 흐름만 파악가능하게 설계
            - 데이터 추상화 
                - 데이터 세부적 속성 / 용도 정의 X
            - 제어 추상화
                - 이벤트 발생의 정확한 절차 방법 정의 X
    - 단계적 분해
        - 하향식 설계 전략 / 추상화의 반복에 의한 세분화
    - 정보 은닉
        - 모듈을 독립적으로 수행할 수 있어 요구사항에 따라 수정, 시험, 유지보수 용이

아키텍처 패턴
    - Layer
        - 시스템을 계층으로 구분 / 구성하는 고전적 방식
    - Client-server
        - 하나의 서버 컴포넌트와 다수의 클라이언트 컴포넌트로 구성
    - Pipe-Filter
        - 단방향 / 필터 이동시 오버헤드 발생
    - Model-View Controller
        - 하나의 모델 대상 다수 뷰 생성 -> 대화형 어플리케이션에 적합하다.

UML(Unified Modeling Language)
    - 고객 / 개발자 간 원활한 소통을 위한 표준화한 대표적 객체지향 모델링 언어 / 럼바우등의 장점도 통합
    ### 인터페이스
            - 클래스 / 컴포넌트가 구현해야하는 오퍼레이션 세트를 정의하는 모델 요소
    - 사물(Things)
        - 구조 / 행동 / 그룹 / 주해(부가적 설명)
    - 관계
        - 연관 관계
            - 2개 이상의 사물이 서로 관련
        - 집합 관계
            - 하나의 사물이 다른 사물에 포함
        - 포함 관계
            - 집합관계 내 한 사물의 변화가 다른 사물에게 영향
        - 일반화 관계
            - 한 사물이 다른 사물에 비해 일반 / 구체적인지 표현
        - 의존 관계
            - 사물 간 서로에게 영향을 주는 관계
        - 실체화 관계
            - 서로를 그룹화할 수 있는 관계
    - 다이어그램
        - 구조 / 정적 다이어그램
            - 클래스 : 관계 및 속성
            - 객체 : 인스턴스를 객체와 객체 사이의 관계로 표현
            - 컴포넌트
            - 복합체 구조
            - 패키지
        - 행위 / 동적 다이어그램
            - 유스케이스
            - 시퀀스
            - 커뮤니케이션
            - 상태
            - 활동
            - 타이밍
            - 상호작용 개요
    ### UI 설계
            - 직관성 / 유효성 / 학습성 / 유연성
            - CLI(텍스트) / GUI(그래픽) / NUI(말, 행동) / VUI(음성) / OUI(사물과 사용자의 상호작용)
        - UI 설계 도구
            - Wireframe
                - 기획 초기 단계에 대략적인 레이아웃 설계
            - Story Board
                - 최종 산출 문서
            - Prototype
                - 인터렉션 적용 / 동적인 형태 모형
            - Mockup
                - 정적인 형태 모형
            - Use CASE
                - 사용자 측면의 요구사항 및 목표를 다이어그램으로 표현
