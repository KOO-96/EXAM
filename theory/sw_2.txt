### API
- 소프트웨어 간 인터페이스
- 운영체제 및 프로그래밍 언어의 기능을 프로그램에서 사용 가능하도록 구현
    -> 개발 비용 저감 / 중복 작업 최소화 / 유지 관리 용이

팬인(Fan-In)
- 자신을 사용하는 모듈 수 --> 팬인 이 높으면 재사용 측면 설계에 우수
    -> BUT 단일 장애점이 높아질 수 있어서 집중적 관리 필요
팬 아웃(Fan-Out)
- 자신이 사용하는 모듈 수 --> 불필요한 호출 가능성이 있어 단순화 필요가 있다.

### 응집도
- 개별 모듈이 독립적인 기능으로 정의되어 있는 정도
    (아래로 갈수록 낮은 응집도)
    - 기능적
        - 모듈 내부의 모든 기능 요소가 단일 문제와 연관
    - 순차적
        - 출력 데이터를 다음 입력 데이터로 사용
    - 통신적
        - 동일한 입/출력을 사용하여 서로 다른 기능 수행
    - 절차적
        - 순차적 수행
    - 시간적
        - 특정 시간 내 처리되는 기능 모아 하나의 모듈로 작성
    - 논리적
        - 유사 처리 요소들을 하나의 모듈이 형성
    - 우연적
        - 서로 관련 없는 요소로 구성
### 결합도
- 개별 모듈 간 상호 의존하는 정도 / 결합도와 품질은 반비례한다.
    (아래로 갈수록 낮은 결합도)
    - 내용
        - 한 모듈이 다른 모듈의 내부 기능 및 자료를 직접 참조
    - 공통 / 공유
        - 공유되는 공통 데이터를 여러 모듈이 사용
    - 외부
        - 한 모듈에서 선언한 데이터를 외부의 다른 모듈에서 참조
    - 제어
        - 한 모듈이 다른 모듈의 상세한 처리 절차를 알고 있어서 ~~
    - 스탬프
        - 동일한 자료구조 조회
    - 자료
        - 자료 요소로만 구성

객체 지향
- 객체
    - 고유 식별자 / 독립된 존재
- 클래스
    - 객체들의 집합
- 추상화
    - 공통적인 속성과 기능 추출하여 정의
- 캡슐화
    - 데이터와 데이터 처리 함수를 하나로 묶음
- 상속
- 다형성

객체 지향 설계 5대 원칙
- 단일 책임 원칙
    - 모든 클래스 / 객체는 하나의 책임만, 완전한 캡슐화
- 개방 패쇄의 원칙
    - 확장에는 Open / 수정에는 Close
- 리스코프 교체 원칙
    - 상위 클래스의 행동 규약을 하위 클래스가 위반하면 안된다.
- 인터페이스 분리 원칙
    - 클라이언트가 비사용 메서드에 의존하지 않는다.
- 의존성 역전 원칙
    - 의존 관계 수립 시 변화하기 어려운 것에 의존한다.

디자인 패턴
- GoF(Gang Of Four)처음 제안하여 구체화
    - 생성 패턴
        - Abstract Factory
            - 구체적인 클래스에 의존하지 않는다.
        - Builder
            - 캡슐화 및 분리하여 객체 조립하여 생성
        - Factory Method
            - 서브 클래스에서 결정하도록 분리
        - Prototype
            - 원본 / 원형 객체 복제
        - Singleton
            하나의 객체만 생성
    - 구조 패턴
        - Adapter
            - 비호환 인터페이스에 호환성 부여
        - Bridge
            - 연결 패턴
        - Conposite
            - 트리 구조로 부분/전체 계층 표현
        - Decorator
            - 객체 기능을 동적으로 추가/확장
        - Facade
            - 단순한 인터페이스로 구현
        - Flyweight
            - 클래스 경량화
        - Proxy
            - 대리 객체 수행
    - 행위 패턴
        - Chain of Responsibility
        - Command
        - Interpreter
            - 언어에 문법 표현 적용
        - Iterator
        - Mediator
            - 복잡한 상호작용을 캡슐화하여 객체로 정의후 중재
        - Memento
            - 캡슐화 유지
        - Observer
            - 상태 변화 시 상속된 객체들의 변화 전달
        - State
        - Strategy
            - 캡슐화하여 상호 교환
        - Template Method
        - Visitor
